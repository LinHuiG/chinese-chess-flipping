# 赛博房间 Android

版本 0.8.1 / versionCode 14，包名保持 com.chessflipping.client。Android Studio 打开本目录；JDK 25、AGP 9.4.0、Gradle 9.6.0、compile/target SDK 37，最低 API 26。

~~~powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
~~~

调试 APK 在 app/build/outputs/apk/debug/app-debug.apk。正式发布使用 Actions 中原有签名，调试签名不能覆盖正式包。

## 使用

默认 **TCP / fqgame.tdcode.tech / 8888**。升级保留服务器设置，设置页“恢复默认值”后“保存设置”生效。可改 HTTP/HTTPS，分别使用 WS/WSS，路径 /ws。模拟器使用 10.0.2.2 访问开发电脑。

大厅选择翻棋（2 人）、黄金矿工（2–3 人）或观影房（最多 6 人）。游戏凑齐设定人数并准备后开局；观影房无需准备，成员可中途加入。房主退出立即解散，不转让。矿工每位玩家操作自己的爪子和购物，房主每 5 秒保存，也可手动保存；重新建房可继续，按加入顺序恢复原座位财富和装备。房主进入后台会暂停矿工。

观影使用 Media3 原生播放器直接向 Emby 取流，网页负责选片、播放控制和房间同步。元数据 API 与初始播放地址必须属于配置的 HTTP(S) Emby 来源；播放内部允许 HTTP(S) CDN 重定向和 HLS 分片，跨源时剥离 Emby/Authorization/Cookie 等账号头与 `api_key`，不会把原地址的查询参数手工带到重定向地址。所有路径拒绝 URL 用户信息，远端页面仍不能进入原生桥。Emby 登录及播放能力取决于实际服务器的账号权限、网络和并发限制。

播放器允许解码器初始化回退；视频解码器在启动后失败且平台还有软件解码器时，本次媒体会话最多重建一次并选择软件解码，保留进度、播放开关、速率和音量。第二次失败仍显示真实错误，不无限重试。原生 `player.renderedFirstFrame` 仅在 Media3 确认首帧已渲染后为真，不能仅凭取得时长或进度判定画面可用；`decoderFallback`、`recovering` 和 `error` 同时提供验收依据。降级效果由主线程真机/模拟器检查，不以本次编译代替播放验证。

翻棋规则、禁止重复棋面、30/60/90 秒或不限时、两侧阵亡统计保持。棋盘真实暗棋只存房主设备。心跳每 5 秒，15 秒未回包时重连，服务端最后有效心跳后 60 秒回收；有效期内可恢复连接。服务器重启使房间失效，矿工本地存档仍保留。

## 实现

App 的 UI、玩法、房主裁判和存档共用 server/src/main/resources/web 的 ES 模块，构建时直接打包为本地 assets。GameService 持有本地 WebView，Activity 重建时重新挂接；不下载远端页面进入 NativeRoom 桥接环境。只允许 appassets.androidplatform.net/web 的本地资源，外部链接交系统浏览器。

Java 保留原生 TCP 自定义 ECDH/HKDF/AES-GCM、OkHttp WS/WSS、UDP socket、设置和 APK 校验安装。P2P 按已获准对端协商密钥，带方向密钥、64 包重放窗口与客户端分片；操作未获房主确认时 400 ms 经服务器重试。Web 玩家或 UDP 不通时服务器转发，HTTP 模式不禁止 App 之间尝试 UDP。

UDP 最大数据报 1200 字节，单对端 256 KB/s 预算；发送大于 28,800 字节的统一帧时返回失败，由共享客户端改走可靠中转，最多 32 个分片避免单帧耗尽重放窗口。只有指定地址正确回应本机未完成挑战后才提升为出站路径，普通认证数据包不能改变出站地址。真实 Wi‑Fi/5G NAT 组合与厂商后台策略仍需真机验收。

已移除自建常驻通知、前台服务和 WakeLock；后台连接尽力保留，系统可停止后台服务。成员后台暂停本地观影并闭麦，回前台同步后由用户再次开麦；房主后台由共享房间逻辑暂停全房。换网重新发现 UDP 地址，已开麦状态不自动恢复。Android 17 请求局域网权限，麦克风权限只在用户点击开麦时请求，拒绝权限仍可观影和发弹幕。

语音采用共同的 CRV1 / IMA ADPCM 16 kHz 单声道 20 ms 独立帧。AudioRecord 采集、编码、UDP 直发或一次指定目标广播，以及 AudioTrack 解码混音均在 Java 内完成；音频包不逐帧经 WebView/JSON/Base64。输入使用 VOICE_COMMUNICATION 与可用的系统 AcousticEchoCanceler，开麦时电影与语音使用相同的通话输出用途；系统回声效果未经过真机验证，界面明确标为未验证，不宣称所有设备能消除电影回声。无系统 AEC 时建议耳机；仍可使用电影、弹幕和闭麦收听。

音频发送队列有独立上限并保留控制消息空间，过期帧在写出前丢弃。接收按流采样时钟和单调时间安排播放，最多积压 6 帧，超过 200 ms 的后续帧丢弃；初始单程延迟未知，作为初始时间基线。64 帧接收窗口允许乱序补洞，低频上报丢包、抖动与排队估计。已写入 TCP 的数据无法撤回。

正式 APK 关闭 WebView 调试，debug 包可用 CDP 验收。测试夹具只打入 androidTest APK。完整打包、跨端联机、真实 Emby、六人外放回声和蓝牙兼容验证以根执行记录为准。

## 0.8.1 原生层复核（2026-10-14）

补齐 WebView 全屏宿主：进入时收起键盘并隐藏系统栏，Media3 画面和弹幕保持在全屏内容上方。可通过网页退出、系统返回或右上角“退出全屏”按钮回到房间；退出全屏不触发退房。`scripts/fullscreen-smoke.cjs` 在 Android 37 模拟器使用本地样片实测三条退出路径，原生视频可见且持续播放，测试房间随后清理。脚本以 `adb input -d 0` 明确选择模拟器显示，避免无目标注入造成误判；截图与结果放在被忽略的 `app/build/fullscreen-checks/`。随后 `PresentationChecks` 仪器检查通过，覆盖 Activity 重建前后选择控件、TCP 握手、3 人矿工建房与断开。

修复原生桥开麦、停麦和配置操作跨线程交错；状态操作统一由主线程依序处理，权限请求在退出、断开或后台时取消，迟到授权不自动开麦。采集发送使用同一房间和目标集合快照，避免切换房间时混用旧帧和新目标；网络调用在音频锁外执行，避免 WS 收发形成锁等待环。后台音频调度不追赶休眠期间错过的定时任务。

Emby 请求移入可独立验证的 `MediaRequests`，元数据使用两条工作线程、最多 16 项等待请求，单次响应最多 2 MiB，并拒绝跨源重定向。播放使用独立的 HTTP 客户端与固定会话代次的 `Call.Factory`，支持 Emby 返回的 CDN 直流和后续 HLS 分片，两类客户端共用取消调度。配置更换（含同源授权更换）或停止播放会取消运行中请求、丢弃排队任务，并在实际网络发送和 UI 回调时再次核对代次；旧播放工厂不能再发起分片或重试。原生播放器保留弹窗请求的隐藏状态，普通进度更新不会重新盖住弹窗；退出后台会释放电影音频焦点。

UDP 清理同时作废待执行的打开/发送任务，发布 Peer 前再次核对代次，旧排队握手不会在换房后复活。主动断开连接同时取消尚未完成的 TCP 更新下载，避免 UI 长时间保留“下载中”。

已执行 `:app:testDebugUnitTest :app:lintDebug -PchessTestSuite=client --offline --max-workers=2`：17 项单测全部通过，lint 为 0 errors、6 warnings。覆盖共同 ADPCM 向量、语音过期/乱序/重复/采样时钟环绕、队列上限、UDP 加密/分片/挑战路径/清理代次，以及真实本机 HTTP 请求取消、迟到回调、元数据跨源拒绝、容量限制、MP4/HLS 请求跨源重定向脱敏、后续 CDN 分片与旧播放工厂失效。测试使用临时 loopback 端口，不访问真实 Emby。权限弹窗、录音设备、音频焦点、Media3 显示、签名 APK 安装与跨端端到端行为仍由主线程装包验收；这些 JVM 检查不替代真机兼容性验证。

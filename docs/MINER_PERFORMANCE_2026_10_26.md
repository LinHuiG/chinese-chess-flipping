# 黄金矿工运动卡顿与抓取偏移修复

2026-10-26，本地实现及定向验收完成，尚未发布。用户反馈 Android/Web 严重卡顿、爪子忽快忽慢或伸出途中停住，询问是否计算与渲染混用线程，并指出抓取物偏离爪心。用户随后明确授权多个子 agent，主线程拆分为模拟/HUD、渲染/抓取、独立性能复现及 UI 复查，最后统一整合。

## 根因与修复

当前模拟、序列化、HUD 和 Canvas 仍在同一 JS 主线程。独立基线显示，在本机手机尺寸、抖动快照和 CPU 降速场景，rAF 持续绘制但爪子姿态停住；数学模拟耗时很小。主要问题是显示时钟和模拟时间处理，并无证据支持为了这部分数学计算改造同步权威接口、引入 Worker。

1. 原渲染每次收到快照都重新在 60–160 ms 内插值到目标；晚包时插值结束后等待，下一包又加速追赶。新 `MineMotion` 按模拟时钟和共用规则速度连续显示，最多预测 500 ms；伸爪遇到已知碰撞/场地边界前停止预测，抓取、积分、爆炸及换关仍由房主裁决。
2. 初始 `elapsed=0` 状态先等待第一个已推进的权威状态，避免资源加载时间变成永久显示领先。收到的显示状态在绘制帧开始时应用，与 rAF 采样共用时钟，避免忙时 rAF 时间戳早于网络回调时间而产生忽快忽慢。
3. 原模拟遇到超过 400 ms 的回调间隔时，计时推进全部间隔，运动却只算 400 ms。现在在本关剩余时长内完整子步推进，摆动反射保留越界余量，移动目标逐子步计算。损坏存档的超大倒计时被拒绝，避免异常补算；商店跨阶段余量维持既有规则。
4. 原物品和爪子分别插值，物品还有 `r × .35` 的额外垂直偏移。现在抓取当帧及回收过程中物品使用爪尖坐标；显示物品中心和贴图高度 77% 处的掌心共用同一点，再应用横竖屏缩放和旋转。
5. 快照发布保留约 100 ms 累积节奏，迟到只发最新状态、不补积压，阶段改变只发布/存档一次。HUD 跳过只有位置变化的更新。公共 SDK 移除每次快照发送、但宿主直接忽略的 `roomActive` 往返，宿主兼容入口仍保留。
6. 断网、后台、暂停、换关及恢复冻结或重置显示状态；重连等待新的权威快照，预测不能改变积分、物品归属或存档。补齐 SDK 原生前后台事件到渲染回调的转发，其他原生事件不再误唤醒矿工；原生前台先于页面可见事件时也能恢复下一帧。

## 可重复对照

运行 `node scripts/miner-performance-smoke.cjs --compare`，使用真实 UI、Canvas、PNG、3 名玩家和第 1000 关。本地基线源码在被忽略的 `server/target/miner-baseline/`；新工作区没有该目录时，默认无参数命令可单独测当前版本。脚本需项目 Playwright/esbuild 和 Edge。

手机场景为 390×844、DPR 3，快照间隔循环 80/240/110/310/90/180/130 ms，每组测量 6 秒。CPU 6× 是 CDP 降速，不等于某台 Android。冻结统计针对避开摆动转折的自由摇摆采样帧，速度低于 0.001 rad/s；过快为超过规则速度 0.85 rad/s 的 1.5 倍。

| 场景 | 修复前冻结帧 | 修复后冻结帧 | 修复前过快帧 | 修复后过快帧 |
| --- | ---: | ---: | ---: | ---: |
| 桌面，固定 132 ms 快照 | 2.61% | 0% | 0% | 0% |
| 手机尺寸，抖动快照 | 39.18% | 0% | 29.38% | 0% |
| 手机尺寸，抖动快照、CPU 6× | 39.39% | 0% | 28.96% | 0% |

修复后三组 p95 摆速均约 0.85 rad/s；CPU 6× 组 draw p95 约 0.8 ms，快照 UI 更新 p95 约 0.6 ms（原约 1.1 ms）。测量期间没有重建/改尺寸的 Canvas，没有大于 50 ms 的 long task。开局等待首个已推进状态出现一次约 87–156 ms 的绘制间隔；后续没有上述运动冻结。不能用这些 CPU 耗时替代 GPU 或实体机帧率。

首轮修复曾在正常手机场景仍有 23.92% 冻结，已追踪到初始时钟领先并进一步发现到包/rAF 时钟混用；修正后增加暖机/相位回归，再作上表最终对照，没有隐去失败。原轨迹 `server/target/miner-performance/current-phone-jitter-failure-trace.json`，最终报告 `baseline-current-report.json`，同目录保存原始轨迹与截图；均为忽略的生成文件。

## 检查与边界

- `scripts/client-test.mjs`：21 组共享检查通过，包含原矿工 1000 关、速度、商店、权威、原生前后台回调与生命周期规则，以及本轮翻棋功能。
- `scripts/miner-simulation-test.mjs`：模拟停顿、摆动反射、伸出/回收速度、阶段超大间隔、移动目标碰撞、抓取/收获、暂停/存档、发布和存档节奏通过。
- `scripts/miner-motion-test.mjs`：抖动速度、500 ms 上限、碰撞预测限制、15 组暖机/计时相位、断线重连、暂停和换关通过。两个新纯逻辑检查已加入 `.github/workflows/publish.yml`，本轮没有触发远程 CI。
- `scripts/miner-render-smoke.cjs`：真实 PNG/Canvas、3 人第 1000 关、延迟 rAF 同帧应用状态、三种画幅下矿石中心与掌心坐标误差小于 0.01 backing pixel。主线程最终整合运行绘制 p95 约 0.2 ms。
- 整合后的翻棋七尺寸、宿主四尺寸、共享布局和大厅/播放器 UI 检查、宿主弹窗检查通过；9 个声明平台的脚本构建通过，语法与差异检查通过。
- 未在 Android/iPhone 实体机、原生 Windows WebView 或真实公网抖动环境验收。此次性能夹具传递本地 JSON 状态，没有测量真实 TCP/WS、MessagePort 和 Android 桥的端到端耗时。
- 未重建 APK/EXE、签名市场或 Docker，未提交推送、发布部署或关机。线上 0.9.3 不包含本次修复；宿主与插件版本暂未改动。

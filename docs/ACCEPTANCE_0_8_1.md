# 0.8.1 全功能验收记录

2026-10-14。用户在 Windows 连接 Emby 时遇到错误的房主权限提示，明确要求所有已实现功能测试后再交付。本轮按功能逐项验收，并覆盖权限、恢复、前后台和异步响应；此要求覆盖此前开发阶段最小测试限制。下面分别记录已验证结果和仍需设备环境的边界。

## 问题与修复范围

- Windows 普通失焦/回焦被当作退后台/恢复，复制片源地址也触发房间同步；默认线上服务仍为 0.7.2，未支持新 ROOM_SYNC。共享客户端把同步失败当成房间结束，但未关闭 Emby 弹窗，再提交即提示“只有房主可以配置片源”。必须分别修正生命周期、失败处理与界面，不取消房主权限校验。
- 进一步检查旧恢复请求和旧媒体登录响应，防止离房/换房后迟到回调清理新房间或带入旧授权。
- READY 显式公布通用能力；缺少 `room-sync`、`room-broadcast`、`host-grant` 的服务在建房/入房前提示升级，版本号只展示，不替代能力判断。
- Android/Windows 原生层一并检查异步媒体、音频与 UDP 清理边界。各路修复及定向检查完成后，由主线程统一构建最终产物和联调。

## 检查入口与证据

- `node scripts/client-test.mjs`：16 组通过，新增兼容能力、恢复隔离、媒体/麦克风迟到回调、翻棋重开、原生终止通知顺序与 2 秒上限。
- Rust：9 项；Windows：15 项；Android JVM：17 项；Java/Rust `TransportV3Test`：2 项通过。Windows 原生 release 链接构建成功；Android 最终 lint 为 0 errors / 6 warnings。
- `scripts/web-smoke.cjs`、`scripts/android-web-smoke.cjs`、`scripts/watch-room-smoke.cjs`、`scripts/app-regression.cjs` 均通过；后者 8 组覆盖真实故障注入，六人脚本新增全屏、筛选、换片及六路旧会话 Stopped 检查。
- 最终 `scripts/native-watch-smoke.cjs` 通过 Windows/Android/网页联调，含全屏、系统 Back 后保留房间、三端终止通知及双向认证 UDP；`android_client/scripts/fullscreen-smoke.cjs` 另验证 JS、Back 与原生按钮三条退出路径。
- Android `PresentationChecks` 实际在 API 37 模拟器运行通过。第一次发现的是测试代码未等待自定义选择面板出现，已改为同时轮询自定义/系统控件再复验，不跳过断言。
- Windows 本次实际启动的程序与设置均在隔离目录；验证恢复默认值后重新切回本机，未改用户保存的设置。用户仍在运行的旧 EXE 不强制关闭；本地打包时保留该文件到被忽略的 `server/target/`。
- 本地截图、网络计数和 JSON 报告保存在被忽略的 `server/target/`；真实 Emby 脚本只从环境变量读取凭据，不入库。

真实片源中曾出现一次浏览器加载失败，复验相同步骤通过；不据此承诺外部 CDN 可用率。HTTP 三端播放/暂停/跳转/弹幕结果已保存，随后截图采集超过 Node 默认缓冲上限，采集器已调至 8 MiB。HTTPS 全程脚本成功并实际查看 Android 视频截图。账号权限和取流能力以真实 Emby 状态为准。

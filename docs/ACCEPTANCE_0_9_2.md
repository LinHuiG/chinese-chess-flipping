## 实现

- 矿工缓存预裁切图集、复用静态背景，减少每帧缩放与分配。
- 电影厅控件紧凑化；清晰度、倍速、音轨、字幕同一行显示当前值并向上展开；原生画面仅裁掉与选项相交的矩形。
- 普通及全屏控制栏约 55px（含进度），按钮约 28px，去掉多余边框；全屏黑底，弹幕为按钮同排短输入框，回车发送，无独立发送按钮。静止五秒隐藏整个底部（含进度），鼠标/触摸/原生交互唤回；输入、拖动、展开选项、错误等待时不收栏。
- 自动下一集、跨季上浮选集、末集停止、剧集存档；旧请求/旧片尾/退出后的结果不覆盖新影片。
- 浏览器拒绝 H.264 10-bit、4:2:2、4:4:4 原画直放，协商 H.264/AAC；同步 PlaybackInfo 查询参数。完整 HLS 按绝对时间跳转，相对截取清单叠加起点并按范围重新协商，避免真实 Emby EXT-X-START 双重偏移。
- 区分原生已核验的跳转确认和浏览器位置确认；只有当前 playbackId/seekId、明确非 seeking、非恢复、非错误、非片尾事件才能确认原生完成，避免实际已经播放却永久广播缓冲。旧事件不能提交新跳转或误报片尾。
- **房主为准**：成员失联五秒暂停等待，连接代次变化后先等房主新状态，再恢复到房主进度；房主缓冲时冻结外推，成员控制不改变房主状态。网络停滞十二秒触发恢复，连续最多两次，持续实际推进后才重置次数；避免协商重叠。
- 服务连接按 DNS/TCP/WS/身份/心跳/发送区分超时；成员十秒未回应标明中转探测超时；Emby 登录、片库、协商、视频等错误分类，片源 URL 脱敏。
- 宿主返回大厅确认框强制隐藏原生视频，插件反复请求显示也不能覆盖；取消恢复先前状态，兼容旧发布插件。
- 木色格线、红黑圆形棋子，双方车和阵亡统计显示「車」；保留整格点击、选中/走子标记和规则。

## 真实片源定位与最终结果

使用原加密存档的独立副本及单独房间，没有修改用户原存档、原客户端或当前房间。早期真实检查中，PC 取得首帧但 Web 晚加入 65 秒未出帧；该失败没有用样片通过替代。后续真实清单证据显示 481 段完整影片时间轴及 EXT-X-START，原实现却再次叠加 StartTimeTicks，导致两端时钟错误；另一条已确认链路是原生完成后实际位置 62.961 秒，JS 仍以目标 60 秒、固定两秒阈值保留 pending，错误冻结房主广播。

集中梳理状态归属、异步所有权、时钟、暂停、恢复预算、定位确认和 UI 生命周期后修订并交叉 review，规则见 [播放适配审查](WATCH_PLAYBACK_REVIEW_0_9_2.md)。最终真实片源整轮通过，Web 实际 1920 宽、readyState=4、播放中，脚本比较原生实际 positionMs 与 video.currentTime，并验证 requestVideoFrameCallback 的实际帧推进。

首轮真实 Emby 曾对分片返回 HTTP 500，恢复后继续通过晚加入和跳转。随后加长解码观察的独立复测，初次及两次恢复的分片均为 HTTP 500、没有首帧；对同一会话分片的独立请求仍返回 500，响应包含明确的 `Error starting ffmpeg`。已核对官方 PlaybackInfo 与停止转码的请求契约；仅凭当前非管理账号和返回信息尚不能确认服务端启动失败的具体原因，不能直接归咎网络或掩盖为通过。

每次首次数据等待最多 60 秒、连续自动恢复最多两次；追加复测约 39 秒进入明确终止状态，没有无限重试。首轮通过证据保存在本机 `server/target/real-source-0.9.2/result-complete-first-pass.json`；后续失败单独保留。用户确认第三方片源、不能管理服务器，不再等待管理员日志；请求结果不含授权 URL、token 或账号。加长至五秒/90 帧的真实源检查未执行到末段，不能标记通过。

自动审批随后拒绝了再次复制原加密配置并启动调试宿主的组合命令，仅返回策略阻止；没有尝试绕过。随后采用单独复制加密配置、单独启动测试宿主的最小操作成功；用户再次明确授权真实片源测试，继续在独立配置与测试房间排查。副本内容在每轮结束时清为 null，文件存在不代表仍保留授权。

测试过程还修正了重复寻找已安装插件的安装按钮、未定义的观测变量、HLS 分片时间误当整集时间，以及 Android 第二次填写密码后未离开输入框的夹具问题。这些不能作为产品修复或真实片源通过的证据。

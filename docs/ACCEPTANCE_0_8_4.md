## 最终候选复验（发布前）

- 确定根因：实际生产 Rust Player 在 HTTP Range 返回 503 时，mpv 会内部跳到最后一帧并给出 EOF、无读取错误；旧逻辑把目标 80 秒误报成 120 秒正常结束。修复保留请求目标，用 SEEK / RESTART 后可达的位置校验确认结果，并防止稳定播放采样突跳片尾。异常时保留目标、显示重试，不广播正常结束。没有认定用户真实 CDN 必然返回 503。
- 实际 Player + 同版 DLL：即时和延迟 10 秒 Range 失败均保留 80 秒、不报 ended，原 URL 重载恢复至 83.04；55 次间隔 190ms / 2 倍速跳转最终 40 → 46.16；暂停跳转稳定在 60；正常片尾仍正常结束。该层使用 null 音视频输出。
- 共享网页：慢 HLS 协商期间只重新协商最新跳转；过期会话清理不触碰当前播放器；新授权从广播或 JOIN 到达只解除失败标记一次。浏览器中止不视为解码失败，网络错误保持播放方式并支持手动重试；明确解码/格式不支持才自动回退一次。16 项定向回归通过，修前分别有旧响应和错误分类红灯。
- 最终 release EXE 已实际启动（独立测试配置），PC 先播放、Web 中途加入，18 次真实鼠标进度点击、前后跳转、自然片尾重播及两端继续前进通过；同时验证 3840×2160 真全屏、窗口精确恢复、成员中转 RTT、DirectComposition 弹幕。此次启动成功，不沿用早期候选因审批阻止而未启动的结论。
- 最终 release 完整进程退出/重启存档验收通过：63 秒、720p HLS、1.5 倍速、音轨 2、字幕 3、音量 0.35/静音在重建后恢复暂停；5 秒保存、成员隔离、重载、82 秒再次保存及删除不复活均通过。网页真实 HTTP/HLS 播放设置、字幕和错误恢复检查通过。
- 最终检查：共享客户端 20 组及 CI 中 11 个脚本通过；服务端 9 项、Windows 33 项通过（1 项需独立媒体夹具的忽略项已另行执行）；Android 21 项 JVM 通过、2 项未配置外部互通跳过，lint 0 错误 / 6 既有警告。Android 构建成功，15 份 HTML/JS/CSS 与冻结源码逐字节一致。

## 2026-10-16 连续跳转补修

- 用户运行的前次本地包确实停在 12:59 / 46:23；点击播放只改变按钮，未恢复进度。用户进程保持运行。读取 Web 现场时电脑操作工具因无法可靠判断浏览器 URL 而终止；没有继续操作或以其他工具绕过。
- 确定修复：mpv 的旧跳转事件不能在新命令 ACK 前积累为新跳转的完成条件；当前 SEEK / RESTART 后还需带代次的异步 time-pos / seeking 回报，不能使用过期的订阅缓存。更旧的属性查询不能确认或覆盖新跳转。原生窗口标题固定，避免暴露媒体 URL 授权参数。
- 原生 `preceding_seek_events_cannot_confirm_the_next_target` 定向测试通过。`desktop_client/scripts/media-seek-events.py` 使用相同 DLL、本地影片、无窗口播放，旧逻辑实测 5/8 错认旧位置，修复逻辑 24/24 正确；该脚本验证独立事件算法，不代替完整应用运行。
- 共享 `scripts/watch-seek-test.mjs` 追加晚加入请求被片源授权发送阻塞时连续定位 580 → 15 秒，旧完成/片尾回报不覆盖目标，成员获得最新位置与播放状态，正确回报后房主继续推进到 15.5 / 16.75 秒。测试通过，原有 HLS offset、EOF 重播等断言也通过；首次运行暴露用例未恢复 offset 的夹具问题，已恢复原有 HLS 前置值后通过。

## 修复

追加用户反馈（同版本仍未发布）：

- PC 持续跳进度：已确认旧跳转完成后播放前进超过 1 秒，固定位置容差会让该跳转持续占位 25 秒。现在确认匹配代次的完成事件，后续请求合并为最新目标并可替代旧操作；满队列 Stop 不阻塞。mpv 属性使用事件缓存，属性写入和字幕 OSD 保持有界异步提交。
- 各端房主观影存档：每 5 秒保存，暂停/跳转变化结束 300ms 后、设置调整、退后台和退出补存；下次创建电影厅恢复最近片源、影片、进度、倍速、画质、音轨、字幕、音量/静音，默认暂停。退出等待写入，网页 pagehide 同步保存。
- 本机房主专属记录：客人共享授权不长期保存；Windows 当前用户 DPAPI、Android Keystore AES/GCM、网页当前浏览器存储。无密码、临时播放 URL、转码会话、成员和麦克风状态。支持不记住以及删除，迟到登录/恢复/定时保存不能复活已删除记录。
- 播放失败和加载期间不以墙钟推进存档；存档恢复的取消标记归属于单次操作。详见 [实现范围](WATCH_HOST_SAVE_PLAN.md)。

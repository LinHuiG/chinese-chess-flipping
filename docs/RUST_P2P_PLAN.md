# Rust 服务端与 Android UDP 直连（2026-09-28）

状态：功能、本地集中检查与 Actions 双架构镜像发布完成；验证结果与未验收范围以 PROJECT_STATUS.md 为准。

## 已确认范围

- server/ 运行时改为 Rust，保留 TCP 二进制协议、HTTP/WS、内置网页、双人房间、房主裁判和服务器断线判负。Android 保持原生 Java。
- 仅支持新版 Android 双方之间的 UDP P2P。Web、旧版客户端以及直连失败的对局继续中转。服务器连接和心跳始终保留。
- 非房主发起申请，房主生成 32 字节随机主密钥，经服务器转发；HKDF-SHA256 派生两个方向的 AES-256-GCM 密钥及 Nonce 前缀。每次 P2P 会话更换主密钥，不进行 UDP ECDH 握手。
- 不根据 HTTP/HTTPS/TCP 模式限制 P2P。用户已明确接受普通 HTTP/WS 分发密钥的链路明文边界。服务器能看到主密钥，不记录密钥日志、不持久化密钥。
- UDP 加密探测确认双向可达后才能切换；保持防重放、业务操作去重、有限重试、断线回退和棋面版本检查。通道切换不暂停或重置每步计时。
- 安卓和 Web 都显示服务器心跳 RTT；安卓显示直连/中转，只有直连成功才显示 UDP RTT。iOS 风格简洁状态胶囊，避免整页刷新。
- 避免重复 JSON 解析/序列化、无意义复制、无限队列、高频空轮询及无变化 UI 更新。
- 开发期间仅做必要编译检查；功能完成后集中验证，不反复全量测试。不得远程部署。

## 实施约定

- Rust 使用 Tokio、Axum、serde_json 和成熟密码库；TCP/HTTP/UDP 共用运行时，保留 TCP_WORKER_THREADS，新增 UDP_PORT（默认 8888）。Docker 上下文仍为 server/。
- 保留旧 Java 实现用于迁移对照和已有客户端规则检查；生产镜像只打包 Rust 程序和静态网页。
- P2P 信令及 UDP 登记凭据绑定当前房间、版本、对局、成员和会话。UDP 映射登记与对端探测使用同一 socket，登记凭据独立于业务主密钥。
- UDP 应用报文上限 1200 字节，超过上限回退可靠通道；第一版不引入分片重组。Nonce 由方向前缀和递增包序号组成，重试使用新序号，业务操作 ID 不变。
- 切换和故障通知经服务器可靠连接协调；房主统一处理两种通道，并按操作 ID 返回已有结果。结算前通过服务器发送最终公开状态，避免跨通道顺序截断末步。
- 文档、协议、交接记录创建和更新后立即 git add；本机配置、缓存、APK、签名不入库。

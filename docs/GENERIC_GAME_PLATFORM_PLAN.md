# 赛博房间框架方案

2026-10-13，已实施版本 v3。每个功能号的必填字段、返回字段和数据流程统一列在 [接入手册](CYBER_ROOM_INTEGRATION_MANUAL.md)。客户端用法见 [开发指南](FRAMEWORK_DEVELOPMENT_GUIDE.md)，实际代码已经迁移到 v3。

0.8.0 已新增不解析业务内容、可指定目标成员的 [通用房间广播](ROOM_BROADCAST_PLAN.md)，客户端成员之间使用 UDP 单播直连，失败目标走服务端广播；同步增加房主声明的通用授权快照。当前接口为下列九功能，验证状态见执行记录。

## 范围

这次允许破坏性更新，将 Rust 收窄为通用通信服务。以后新增游戏、文件共享、直播或观影，只扩展 App/Web 的控制头、正文协议和界面，不为这些功能增加 Rust 分支。

| 位置 | 负责内容 |
| --- | --- |
| Rust | 房间目录、转交准入申请/裁决、执行房主声明的路由授权、退出/关闭、身份、地址发现、定向转发和广播 |
| 客户端公共框架 | 连接服务端、按目标发送、直连适配、房主准入和获准成员管理 |
| 客户端功能模块 | 自己需要的控制字段、正文、业务规则和状态 |

房主决定准入、踢人和权限；业务是否由房主裁判由模块决定。Rust 记录通用 grant/revoke 声明，不解析密码、allowed 或其他业务正文。

## 九个基础功能

| 功能号 | 功能 | 结果 |
| --- | --- | --- |
| 100 | CREATE | 创建房间，当前客户端成为登记房主 |
| 101 | LIST | 按公开 roomType 查询 |
| 102 | JOIN 加入房间 | 将申请转给房主，房主裁决后将结果返回加入者 |
| 103 | ROOM_SYNC | 获准成员读取授权快照；房主更新锁标记或撤权 |
| 104 | LEAVE 退出房间 | 退出并通知房主；房主退出则关闭房间 |
| 105 | CLOSE | 登记房主关闭房间通信资源 |
| 200 | SEND | 向指定 clientId 透传控制头扩展和正文 |
| 201 | BROADCAST | 全体或指定获准接收者，不回发来源；正文透传 |
| 210 | UDP_DISCOVER | 观察客户端 UDP 地址 |

入房直接调用 JOIN：服务端查找房主并转发申请，房主用同一功能号与 requestId 回复，服务端返回原样裁决和可信房主来源。申请者得到 allowed 及房主附带信息；房主 ID 由结果控制区 from 提供。服务端维护请求对应关系，不解析 allowed，不替房主批准。功能标识 A+B 的 A 用于服务端索引，B 由房主检查，B 不作为密码。通信关联是内部送达资源，房主获准集合才表示正式成员，两者都使用 clientId。

## 转发契约

TCP、WS、UDP 共用 17 字节固定头，控制区使用 `key:value` 加 LF。普通管理正文为 JSON；客户端消息正文可以是 JSON、文件块、媒体字节或密文。UDP 每份数据报装一个完整帧，不另设 CFP1 或 CRD3 外壳。

SEND 只要求 op、roomId、to；requestId 在需要服务端入队结果时才提供。其余非保留控制字段由客户端定义，服务端按原始字节和顺序透传，正文也不改。服务端读取路由、验证连接来源，将包类别改为对端消息并追加可信 from，不重新编码业务控制字段。

不强制嵌套第二个客户端帧，不强制 type、messageId、状态序号、文件偏移等扩展字段。未来 3A 游戏需要什么，由它自己的协议决定。接收框架根据可信来源和房主决定校验业务准入。

TCP 继续原有 ECDH/HKDF/AES-GCM，不改用标准 TLS 库；协商收敛为请求公钥、返回公钥、客户端协商与身份申请三条消息，再由 READY 返回接入结果，kind 依次为 1、2、3、4。Java/Rust 已验证合并握手互通；现有网页 HTTPS/WSS 部署不变。UDP 地址登记也用统一帧；数据怎么探测、分片、重传和重组由客户端适配器约定，Rust 不处理这些 P2P 数据包，服务器中转仍走 TCP/WS。

## 本版不提前加入的内容

不设计辅助连接、lane、三步入房提交、短期传输许可、通用文件流功能号或媒体字段。指定广播、通用授权关联代次以及 discard/maxAgeMs 是本次明确需求所需的基础扩展；保留身份绑定、包长度、连接回收和有界队列，不扩张成业务协议。

## 实施与发布

基础服务、三端共享界面、翻棋、2–3 人矿工及 1–6 人 Emby 观影已实现。新增模块继续只扩展客户端。网页资源与安装包和 Rust 程序分层；发布替换后统一重启服务以更新运行时快照。默认 TCP / fqgame.tdcode.tech / 8888 及升级保留设置继续生效。

首次升级需要协调 v3 服务端和客户端，允许破坏旧协议兼容。本地已完成规则、恢复、TCP/WS、UDP 分片和 App/Web 混合联机检查；公网打洞、实体手机兼容和文件/直播等未来模块未验收。发布与两台服务器部署以 PROJECT_STATUS.md 最新记录为准。新增客户端字段与正文不要求改动 Rust 源码。

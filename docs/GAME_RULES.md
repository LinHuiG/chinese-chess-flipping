# 翻棋游戏规则与棋局方案

归档日期：2026-09-27（Asia/Shanghai）。

状态：**用户已确认规则，尚未实现。** 本次仅归档讨论结论并更新其他线程的接续入口，没有开始业务编码。房间、连接、退出及重连规则另见 [房间管理、连接清理与自动重连方案](ROOM_MANAGEMENT_PLAN.md)。接续前同时阅读根目录 [PROJECT_STATUS.md](../PROJECT_STATUS.md)、[README.md](../README.md) 和实际代码。

本文第 1～6 节记录确认后的规则及其直接含义，第 7 节为配套实现建议。不要用其他翻棋或传统象棋规则替换本项目规则；归档不代表实现或验收完成。

## 1. 棋盘、棋子与开局

1. 棋盘竖向显示，为 **4 列、8 行，共 32 格**，棋子放在格子内。
2. 使用红黑双方全部 32 枚象棋，每方 16 枚：将/帅 1 枚，士、象、车、马、炮各 2 枚，兵/卒 5 枚。红黑名称差异不改变对应种类的规则。
3. 开局把全部棋子打乱，反面朝上，每格放一枚。未翻开的棋子称为暗棋，翻开后称为明棋。
4. 随机选择一名玩家先手；先手不固定为房主，也不固定为红方。
5. 先手第一回合翻开一枚暗棋，其颜色成为先手本局颜色，另一名玩家获得另一颜色。第一次翻棋占用第一回合，随后轮到后手。
6. 房主开局前为本局指定每步时间限制，见第 5 节。

## 2. 回合与通用规则

1. 双方轮流行动，每回合只能选择翻开一枚暗棋，或者移动一枚己方明棋。吃子属于一次走子，完成后换人。
2. 翻棋可以选择棋盘上的任意暗棋；翻出对方颜色同样结束本回合，不额外获得行动机会。
3. 暗棋不能作为起点移动。移动不能越出棋盘，起点与落点不能相同；除马的斜向走法外，所有走法沿上下左右方向。
4. 己方明棋不能被己方吃掉，落点也不能与己方明棋重叠。只有第 3 节明确允许的特殊吃法可以吃暗棋，且不受暗棋实际颜色限制。
5. 吃子后，被吃的棋子移出棋盘，行动棋子移动到目标格并保持明棋。暗棋被吃时向双方公开其颜色和种类，即使是自己的暗棋也正常移除。
6. 明棋和暗棋都属于占用格子的棋子；车、炮直线移动所说的障碍物包含两者。
7. 所有走法还必须符合第 4 节的禁止重复棋面规则。无效操作不改变棋盘、不换人，也不重置本回合计时。
8. 将帅没有必须保留的特殊地位，没有“将军、应将”要求；将帅被吃掉本身不直接结束对局。

## 3. 各类棋子的走法与吃法

下表的“相邻”指上下左右一格；“斜向一格”指四个斜对角相邻格。表中对明棋的吃法都只允许吃对方明棋。

| 棋子 / 走法 | 移动到空格 | 吃对方明棋 | 吃暗棋 | 路径要求 |
| --- | --- | --- | --- | --- |
| 将/帅 | 上下左右一格 | 将/帅、士、象、车、马、炮；不能吃兵/卒 | 不允许 | 相邻 |
| 士 | 上下左右一格 | 象、车、马、炮、兵/卒；不能吃将/帅或士 | 不允许 | 相邻 |
| 象 | 上下左右一格 | 车、马、炮、兵/卒；不能吃将/帅、士或象 | 不允许 | 相邻 |
| 车：直线一格 | 允许 | 马、炮、兵/卒 | 不允许 | 相邻 |
| 车：直线两格及以上 | 允许 | 任何种类 | 允许，包括己方暗棋 | 起点和落点之间所有格子必须为空 |
| 马：上下左右一格 | 允许 | 炮、兵/卒 | 不允许 | 相邻 |
| 马：斜向一格 | 允许 | 任何种类 | 允许，包括己方暗棋 | 不判断“蹩马腿”，旁边有棋子不影响 |
| 炮：直线移动到空格 | 上下左右任意正整数格 | 本行不适用 | 本行不适用 | 起点和落点之间无棋子，落点也必须为空，不能跳过棋子落到空格 |
| 炮：上下左右一格吃子 | 本行不适用 | 仅兵/卒 | 不允许 | 相邻，不需要炮架 |
| 炮：隔一枚棋子跳跃吃子 | 不允许打空炮 | 任何种类 | 允许，包括己方暗棋 | 沿一条直线，以遇到的第一枚棋子为炮架，吃第二枚棋子 |
| 兵/卒 | 上下左右一格 | 仅将/帅，不能吃兵/卒或其他种类 | 不允许 | 相邻 |

### 3.1 炮的补充定义

- 从炮的起点向所选方向扫描，忽略空格，遇到的第一枚棋子作为炮架；炮架可以是红棋、黑棋、明棋或暗棋。
- 遇到的第二枚棋子是唯一的跳跃吃子目标。目标是对方明棋或任意暗棋时可吃；若是己方明棋则不能吃，也不能越过它打第三枚。
- 炮架不被移动或移除。吃子成功后，炮落在目标格。
- 只有炮架而没有第二枚棋子时，不能跳跃吃子，不能打空炮。

### 3.2 同类相吃

- 普通吃法中只有将帅可以互吃；士不能吃士，象不能吃象，兵卒不能互吃。
- 车的非相邻直线吃法、马的斜向吃法、炮的隔子跳跃吃法可以吃对方任何种类，因此也能吃对方同类。
- 不增加其他象棋中的同级互吃、马走日、象走田、兵过河或九宫限制。

## 4. 禁止重复棋面

### 4.1 相同棋面的定义

1. 只比较棋盘上固定位置的 32 个格子，不考虑轮到谁行动。
2. 每格按“空格 / 暗棋 / 明棋的红黑颜色与种类”比较；暗棋的隐藏身份不参与棋面比较。
3. 同色同类棋子视为相同，不使用棋子的个体编号区分。例如两枚红车交换位置后，其余格子不变，仍然算同一棋面。
4. 任何会形成已记录棋面的走法都是非法走法，必须拒绝；拒绝后仍由当前玩家在剩余时间内行动。
5. 不采用“重复若干次才判和”或“连续若干步不吃子判和”的规则，本方案没有和棋规则。

### 4.2 历史缓存

1. 房主 App 在内存保存本局历史棋面，并负责判重。
2. 开局记录初始棋面。合法的不吃子走棋完成后，把新棋面加入历史。
3. **每次合法吃子或翻开暗棋后，清空旧历史，再记录操作后的当前棋面。** 不得清空后漏掉当前棋面，否则会错误允许之后绕回该棋面。
4. 吃子减少棋盘上的棋子总数，翻棋减少暗棋数，因此操作后不可能恢复到该操作之前的棋面，旧历史可以清理。
5. 非法操作、选中棋子、取消选中等不改变历史。对局结束后清理本局缓存，新局重新建立。
6. 判断是否有合法走法时，必须同时过滤重复棋面的走法；不能只检查棋子本身能否到达目标格。

## 5. 每步时间限制

1. 房主在开局前指定本局设置，只有 **30 秒、60 秒、90 秒、无限** 四个选项，对双方一致。
2. 有限时间模式下，本局开始时给先手开始计时；每次合法行动完成并换人后，给下一名玩家重新开始完整的每步计时。第一次翻棋也受限制。
3. 这是每回合的时间限制，不是整局总用时。无效操作、重复棋面操作不重置计时。
4. 当前玩家超时直接判负，对方获胜。
5. “无限”仅取消每步超时限制，其他胜负条件照常生效。
6. 四个选项已确定；界面默认选项、具体计时同步和协议字段尚未实现，不把某个默认值记为用户指定。

## 6. 胜负与房间生命周期

| 条件 | 结果 |
| --- | --- |
| 某方全部棋子被吃光 | 该方立即判负，对方获胜，无需等待该方下一回合 |
| 轮到某方时，棋盘没有暗棋，且该方没有任何合法走法 | 当前行动方判负，对方获胜 |
| 原本存在可到达的走法，但全部会形成重复棋面，且没有暗棋可翻 | 同样属于没有合法行动，当前行动方判负 |
| 有限时间模式下当前行动方超时 | 当前行动方判负，对方获胜 |
| 游戏中某方退出、断线、心跳超时或被同 App 新连接替换 | 沿用房间方案，退出者判负 |
| 游戏中房主主动解散房间 | 沿用房间方案，先按房主认输处理，再解散 |

- “全部棋子被吃光”按该颜色在棋盘上剩余的全部棋子统计，**包含尚未翻开的暗棋**。没有己方明棋，但还存在己方暗棋，不等于被吃光。
- 只要尚未触发立即判负条件，有暗棋就仍可通过翻棋行动。无暗棋时，普通移动和吃子都属于要检查的合法走法。
- 正常结束，包括棋子被吃光、无合法行动及每步超时，双方留在房间并回到未准备的等待状态；退出与解散后的处理按房间方案执行。
- 随机先手和颜色分配不会改变退出、断线或超时判负；第一枚暗棋尚未翻开时，仍可按玩家身份确定败方。

## 7. 配套实现建议与接续范围

本节是为实现上述规则提出的建议，不代表已经确定类名、报文字段或底层实现。

- 继续采用房间方案的职责划分：房主维护棋盘、暗棋真实身份、回合、颜色、历史棋面和正常胜负判断；其他成员通过服务端向房主提交操作，房主经服务端同步结果。服务端仍负责房间状态、会话清理和退出导致的强制结束。
- 随机布局、先手及本局时间设置应由房主统一确定并同步；普通游戏界面不提前显示暗棋身份，被吃掉的暗棋则向双方公开。
- 计时建议由房主统一裁决，使用单调时钟，操作处理与超时结束按同一顺序裁决。双方界面的倒计时用于展示，不能分别独立宣布相互冲突的结果。具体网络延迟处理尚未实现。
- 使用统一的合法动作判断处理用户操作、可走提示和无棋可走判定，确保车/马/炮特殊吃法、暗棋和历史判重一致。
- 棋面使用固定顺序的完整格子编码进行精确比较；若用哈希加速，也应避免仅凭可能碰撞的摘要判负。不要把行动方或同类棋子的个体 ID 放入判重键。
- 对合法动作先计算结果，检查判重后再提交；吃子后检查剩余棋子数，没有结束才换人检查合法行动并开始下一回合计时。非法动作不得提前修改历史或计时。
- 沿用本局 ID、回合/状态版本来拒绝迟到或重复操作。结束、退出和超时处理应保证本局只结算一次；结束后清理定时任务、历史及旧操作。
- 房主离线按退出判负结束本局，不迁移进行中的棋盘或历史；重连回大厅，不恢复棋局。这与已确认房间方案一致。
- 本轮仅归档，没有授权开始业务实现。后续按用户的新开发指令确定房间和棋局的实施范围，不再重复询问本文已经确认的规则，也不把占位棋盘当作完整游戏。

# 电影厅房主存档方案

2026-10-15。对应用户“片源、播放进度等可以房主存档，不必每次重新输入”的方案请求；本文件是设计，不代表持久存档已经实现。现有 `cyber.emby.base` 只保存地址，房间恢复快照不等于独立观影存档。

## 用户流程

房主首次连接片源时选择“在本机记住片源”；影院保留独立的片源设置和片库。下次建电影厅可选择已保存的片源，片库展示“继续观看”，明确影片/剧集名与上次进度。恢复后先暂停，由房主开始全房播放，避免新建房间自动出声。

设置中提供“退出此片源”“删除此片源及观看记录”和独立清除历史。授权过期时只要求重新登录，保留观看进度；影片下架时提示重新选片，不丢掉其他记录。

## 保存范围

| 数据 | 保存方式 |
| --- | --- |
| 片源 | 用户自定名称、基础地址、服务器标识（可取得时）、用户标识和访问令牌；不保存原始密码 |
| 观看记录 | 片源标识、影片 ID、片名、剧名及季集编号、实际播放秒数、总时长、最后观看时间；以片源与影片组合为键，保留最近有限条记录 |
| 偏好 | 本机音量、清晰度偏好；房主恢复时可带上所选倍速，但全房开始仍需主动操作 |
| 不保存 | 旧房间号、成员列表、麦克风开启状态、播放中的 URL、转码会话及短期票据 |

仅保存房主自己登录的片源，成员收到的房间授权不自动转为自己的长期片源。第一阶段仅本机，不增加服务端账号与云同步。

## 时机与恢复

每五秒保存实际已播放位置，暂停、提交拖动、换片、退出与进入后台时补存。以播放器时间加转码起点计算完整位置，不把关闭应用期间的墙钟时间算作播放。

仍有效的房间先走原房间恢复；原房间已解散时创建新房间，使用新的播放代次和成员准入。不能复用旧房间或 HLS 会话来冒充恢复。片源令牌有效性由重新取片确认，失败时显示重新登录。

Android 用系统 Keystore 保护本机保存密钥，Windows 使用当前用户范围的 DPAPI 保护令牌；网页须显式选择记住，说明同一浏览器配置下保存授权，不声称普通 localStorage 已加密。原始密码只用于登录请求。[Android Keystore](https://developer.android.com/privacy-and-security/keystore)、[Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) 为实现参考。

## 验收重点

关闭后重开、退出再建房、同片源多影片、连续剧换集、拖动后保存、HLS 非零起点、无时长条目、令牌失效与影片下架；普通成员不持久化共享授权，退出/删除后令牌不可再由旧异步请求写回。不得在日志、截图、导出文件或仓库中保存密码与令牌。

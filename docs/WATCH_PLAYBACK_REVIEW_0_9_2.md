## 能力边界

Web 使用 Hls.js 处理 HLS/MSE，Windows 使用 mpv，Android 使用 Media3。项目负责 Emby 授权及协商、片源时间换算、房主状态和本机生命周期，不自行实现解码器、复用器或 HLS 下载引擎。

Emby 的完整清单不等于所有片段已经生成。绝对时间轴也不等于服务端承诺任意片段都可无条件复用编码；跳转失败仍必须有截止、反馈和有限恢复。

## 集中规则

| 对象 | 规则 |
| --- | --- |
| 房间播放状态 | 房主拥有影片、进度、播放意图和倍速；成员音量、清晰度、音轨、字幕各自独立 |
| 当前载入 | 固定房间上下文、generation、影片 epoch 和授权；每次异步继续及清理后的递归载入都重新核对，旧任务不能停止或覆盖新会话 |
| 播放时钟 | `影片位置 = 播放器位置 + offset`。完整 Emby 清单 offset=0；从指定起点截取的相对清单才叠加起点。清单只解析一次并返回类型与偏移 |
| 初次定位 | Hls.js 使用明确 startPosition，自行完成首次载入；不在 metadata 回调中抢先强制另一次定位。原生及直接视频按各自接口确认定位 |
| 会话切换 | 完整清单按播放器时间跳转；相对清单需要新起点或超出有限范围时重新协商。所有终止只针对捕获的 PlaySessionId/DeviceId，不按共享影片广泛取消 |
| 实际位置与意图 | 进行中的 seek 保留目标；健康且同 epoch 才采样播放器实际位置。失败、恢复和保存不能用旧帧位置覆盖目标 |
| 首次数据 | 明确区分 metadata-only 暂停、实际取帧和等待浏览器播放许可。真实取帧/metadata 请求有 60 秒截止，合法暂停和等待用户许可不误报片源异常；明确用户解锁可重新计时 |
| 后续定位 | 已出首帧的原生 seek 最多 30 秒、浏览器最多 60 秒；首次载入不误套后续 seek 时钟 |
| 定位完成 | 原生必须明确匹配当前 playbackId 与 pending seekId，显式非 seeking、非恢复、非错误、非片尾，才接受其已核验的实际位置；不能再用浏览器固定两秒阈值否决原生完成。浏览器及片尾事件仍核对目标附近位置，旧事件不能提交新跳转 |
| 暂停与缓冲 | 统一 shouldPlay。成员因房主缓冲而正常暂停时，不消耗本机恢复次数；暂停后恢复有一次进度宽限，首帧时钟保持独立 |
| 自动恢复 | 同一影片/授权最多连续两次，自动 reload 不重置预算；新影片、新授权或手动重试可重置。三个连续、健康的实际推进样本才重新允许自动恢复，抖动/缓冲/回退不算 |
| 重连 | 成员保持暂停，等待新连接代次下的房主新状态后再恢复；不能拿本机旧时间自行续播 |
| 异步播放结果 | play/unlock 的成功或拒绝只影响仍匹配的载入；只有 NotAllowedError 提示用户解锁，切源产生的 AbortError 不冒充权限问题 |
| 界面刷新 | render 只刷新界面，不启动载入。UI 显式 update，不通过 DOM observer 反复改写控制状态 |
| 控制区 | 普通及全屏五秒闲置隐藏整条底栏；输入、拖动、选项和必要异常/加载反馈保持可见。reset 清理计时器，迟到事件和发送结果不污染退出或新草稿 |

首帧失败、后续停滞和跳转失败分别判定；达到恢复上限后停止加载并明确要求手动重试。Hls.js 的单片段等待不可以绕过整个操作截止。

## 审查与验收方式

先检查调用路径、所有权及异步顺序，集中修改后交叉 review。测试作为结果验收，区分测试夹具、受控故障、真实片源和最终载荷。全片 HLS 夹具保留 `MEDIA-SEQUENCE:0`、完整 EXTINF 和 `EXT-X-START`，同时保留截取清单，避免只测一种服务器行为。

实际检查要求原生和浏览器都取得解码帧，比较当前实际进度，而不是只比较界面目标或固定几秒前的跳转值；覆盖晚加入、前后跳转、暂停恢复及成员断网后追随房主。输出仅保留脱敏的时序、状态、片段编号和 HTTP 状态，不归档授权 URL。
